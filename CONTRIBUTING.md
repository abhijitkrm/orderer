# Contributing

This is the **specification repo**. It holds the contract that keeps every
orderer implementation honest. Implementations live in `orderer-<lang>`
repos, checked out as siblings, and each vendors a copy of `spec/` +
`vectors/`.

## Two layers of spec

| Layer | Lives in | Changed by |
|---|---|---|
| Matching semantics (books, events, snapshots) | `spec/matcher/`, `vectors/matcher/`, vendored from [matcher](https://github.com/abhijitkrm/matcher) | changing matcher first, then re-vendoring (`docs/VENDORED.md`) |
| Pipeline contract (routing, journals, ordering, durability, harnesses) | `spec/*.md`, `vectors/{routing,pipeline,recovery,journal}/` | this repo |

Never edit `spec/matcher/` or `vectors/matcher/` here; `scripts/vendored.sh`
fails if you do.

## The spec-first workflow

1. A **pipeline change** starts in `spec/`. It gets a vector that tests
   it, generated by the reference implementation (`orderer-rust`) and
   audited by hand.
2. The change then lands in every impl repo. Each re-vendors `spec/` +
   `vectors/` and must produce byte-identical output.
3. Ports are ports: no language-specific observable behavior. Threading
   models may be idiomatic; outputs may not differ.
4. Anything observable (stdout, journals, snapshots, routing) must be
   specified in language-neutral terms. "Whatever orderer-rust does" is not
   a spec.

## Verify

```bash
scripts/vendored.sh   # vendored matcher copy untouched
scripts/manifest.sh   # every vector listed, every listed file present
scripts/verify.sh     # each present impl's golden suite
scripts/diffuzz.sh    # differential fuzz across impls (+ matcher)
scripts/exhaustive.sh # bounded exhaustive equivalence
scripts/e2e.sh        # journal/snapshot/recovery loop + cross-restore matrix
scripts/snapdiff.sh   # snapshot byte-parity vs matcher
```

## Benchmarks

Follow `spec/BENCH.md` and report the environment (CPU, OS, flags, journal
mode). No unattributed numbers go in `docs/RESULTS.md`.
